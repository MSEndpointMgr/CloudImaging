# Implementation Plan: Security Hardening Refinement

**Branch**: `002-security-hardening-refinement` | **Date**: 2026-07-15 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-security-hardening-refinement/spec.md`

## Summary

Harden existing session security controls in the current CloudImaging architecture
without changing deployment boundaries. The implementation introduces three aligned
workstreams: passcode abuse controls on coupling endpoints, token replay prevention
across all device-session authenticated operations, and centralized sensitive-data
redaction enforcement for logs/telemetry. The design keeps authorized imaging
workflows intact, adds security observability, and introduces CI checks that fail
on secret leakage patterns.

---

## Technical Context

**Language/Version**:
- .NET 10 (`net10.0`) for DeviceGatewayApi, OperatorApi, ImagingCoreApi, and shared contracts
- .NET 10 (`net10.0-windows`) for Cloud Imaging Client and Cloud Imaging Media Builder
- Node.js 22 + TypeScript for Cloud Imaging Portal backend
- TypeScript (React 19) for Cloud Imaging Portal frontend

**Primary Dependencies**:
- Azure Functions isolated worker (`Microsoft.Azure.Functions.Worker` v2)
- `Azure.Data.Tables` for security state, counters, and policy records
- `Microsoft.Extensions.Logging` with centralized log-enrichment/redaction components
- `Microsoft.Identity.Web` for operator-facing token validation
- Existing portal/backend test stack (Vitest + Supertest) and .NET xUnit test projects

**Storage**:
- Azure Table Storage (abuse counters/events, token validation records, redaction policy metadata)
- Existing session and telemetry sinks remain in place; this feature adds policy and audit records

**Testing**:
- .NET: xUnit unit/integration tests for coupling, token validation, and redaction filters
- Node.js/TypeScript: Vitest integration tests for operator-facing behavior and response safety
- Contract tests for updated request/response semantics
- CI security scan tests for prohibited sensitive values in logs and diagnostics

**Target Platform**:
- Existing CloudImaging deployment topology (Azure Functions + App Service + Static Web Apps)
- WinPE client + Windows desktop Media Builder remain unchanged in runtime target

**Project Type**:
- Polyglot distributed application with API contracts, shared security policy, and cross-service telemetry

**Performance Goals**:
- Maintain existing baseline with no more than 10% p95 latency increase on coupling and polling paths
- Preserve successful authorized end-to-end imaging workflow behavior under baseline load

**Constraints**:
- No hardcoded environment secrets; startup validators must reject launch when required security parameters are absent or use insecure placeholder values
- Safe error responses only; no sensitive data disclosure
- Replay defenses must allow benign retry behavior while blocking abuse; valid retries are distinguished by client-provided idempotency keys or request nonces within an approved retry window
- Token expiry validation MUST apply a configurable clock skew tolerance window (default: 30 seconds) so legitimate clients with minor clock drift are not incorrectly rejected; tokens presented outside the tolerance window are rejected
- Device-session tokens MUST be revoked immediately when their associated session reaches a terminal state (SessionCompleted, SessionFailed, SessionNotAuthorized); revocation takes effect on next validation without waiting for natural expiry
- Redaction policy must apply before persistence in normal and exception paths for all four server components: DeviceGatewayApi, OperatorApi, ImagingCoreApi, and portal backend
- Passcode abuse proxy behavior in OperatorApi must be validated by contract tests to ensure Imaging Core API decisions are correctly forwarded without disclosing sensitive internals
- Security integration tests MUST run against real Azure endpoints with short-lived managed identities in an isolated staging resource group; HTTP-layer mocking is forbidden for security tests per constitution Principle III
- Must remain compliant with constitution quality gates (zero-warning build, test-first, integration coverage)

**Scale/Scope**:
- Covers all session coupling paths and all device-session authenticated operations
- Security telemetry required for 100% of blocked passcode/replay decisions including terminal-state token revocation events
- Redaction and correlation enrichment applicable to all logs/traces generated by DeviceGatewayApi, OperatorApi, ImagingCoreApi, and portal backend (all four server components)
- Multi-origin distributed abuse fingerprinting covers composite session+source-hash keys across all configured source dimensions
